# 短信推送助手 / SmsForwarder Assistant · Bark-Android v1.3.5

## 中文

此 GitHub Release 提供源码 ZIP 和 tar.gz。

网络恢复时，助手通知本机 Bark 引擎提前重试积压的通知。只有上一次因连不上网络、连接被重置或超时而失败的通知才可提前投递。系统重新获得可用的默认网络，或该网络的 IPv6 默认路由恢复时，助手会发出通知。重复事件合并，积压通知分批处理，原有通知 ID 与持久队列保留。

Apple 返回限流、设备令牌失效、服务端错误或证书校验失败时，继续执行原来的退避。升级前留下的待投递记录继续按其已保存的时间重试。助手在本机通过子进程管道触发重试。

已接受的通知如果含有格式错误的可选分组字段，引擎会略过该字段并继续投递，避免反复在同一条通知上崩溃。

已启用的 Bark 主进程退出时，守护会先恢复前台服务，再进行完整检查。手动停用、首次解锁和重复故障退避条件继续生效。

队列与本机 HTTP 检查通过，包括进程重启、重复网络回调、限流和令牌错误。实际 iPhone 通知送达需要端到端验证。

## English

This GitHub Release distributes source code in ZIP and tar.gz archives.

The Android service prompts its local Bark engine to retry pending notifications when Android reports a validated default network or a restored IPv6 default route on that network. Only transport failures such as connection resets, timeouts and unreachable networks qualify. The engine coalesces notifications from Android, staggers eligible retries and retains each notification's original ID.

Provider rate limits, invalid tokens, server errors and certificate failures keep their existing backoff. Records from earlier versions retain their saved retry times. The service signals the engine through its private child-process pipe.

An accepted item with a non-text optional group is delivered without that group, so it cannot repeatedly crash the queue worker after a restart.

When an enabled Bark main process exits, the monitor requests its foreground service before the full checks. Manual stop, device-unlock and repeated-failure backoff checks still apply.

Queue and local HTTP checks cover restarts, repeated connectivity events, throttling and token errors. Actual delivery to an iPhone requires an end-to-end test.
